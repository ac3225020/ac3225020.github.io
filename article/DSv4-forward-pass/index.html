DeepSeek-V4 前向传播全流程（推理视角）

基于 model.py 的推理代码，从用户输入到下一个 token 的完整过程。
每个步骤：先讲最简实现 → 再讲 DSV4 的实际优化 → 标明输入/输出矩阵形状。

0. 全局认知：两个角色

整个推理过程只有两种东西：

角色 内容 特点
权重（固定） 嵌入表 E、每层 wq/wkv/wo、专家矩阵、输出矩阵 W 训练好后冻结，推理时只读；几十 GB，每步都要从显存读一遍
激活（现算） x、h、q、kv、logits 根据输入现场计算，用完即弃（K/V 例外，会缓存）

推理 = 固定的知识 × 变化的输入 → 当场的预测。

1. 总体执行框架

2. 步骤一：分词与嵌入查表

最简实现（分词与查表）

分词器把文本切成 token id 序列；嵌入表 E 是一个 [词表, dim] 的矩阵，按行号查表（不是矩阵乘），每个 id 换一行向量。

  • 输入：ids [S]（整数序列）
  • 输出：x [S, 4096]（每行一个 token 的向量）

DSV4 的优化（ParallelEmbedding）

ParallelEmbedding（L83）：多卡时把 E 按词表维度切分到不同显卡，各自查自己那一段再 all_reduce 合并。单卡时就是普通查表，无差别。

关键点

嵌入向量只是 token 的"原材料"。decode 时历史 token 永不重新查表——它们的贡献已经以 K/V 形式存进 KV cache 了。

3.1 Attention（核心）

这是唯一发生 token 之间信息交换 的地方。其余所有操作都是逐 token 独立的。

3.1.1 Q/KV 投影

最简实现（标准 Transformer）：

含义：每个 token 生成三个角色——Q（我在找什么）、K（我是什么的标签）、V（我的实际内容）。

DSV4 的优化（MLA，Multi-head Latent Attention）：

MLA 核心思想：64 个头的多样性全部由 Q 侧承担（每个头的 q 不同，查同一份 kv 自然得到不同结果）；KV 只存一份共享的 512 维"信息浓汤"，既是 K 也是 V。
收益：KV cache 每 token 只存 512 个数（标准 MHA 要存 64×512×2=65536 个），省 128 倍显存。

3.1.2 RoPE 位置编码（L499、L504）

最简实现：纯注意力对顺序无感知，必须注入位置信息。RoPE 把 q/kv 的最后 64 维两两一组做旋转，旋转角度随位置变化，使得 q_t · kv_s 自动携带相对距离 (t−s) 的信息。

DSV4 细节：只旋转最后 64 维（rope_head_dim=64），前 448 维保持内容纯净；且输出后要"反旋转"（L534），因为 kv 兼作 V，旋转会被加权求和带进输出。

3.1.3 注意力核心计算

最简实现（三步）：

  • 输入：q [S, 64, 512]，kv [N, 512]
  • 输出：o [S, 64, 512]（列数跟随 V 的行维度）

矩阵乘法的每个元素就是一次点积：q·kvᵀ = q 和 kv 每一行分别点积的打包写法。
1/√512 防止维度大时点积数值爆炸导致 softmax 饱和。
因果掩码：位置 t 只能看 ≤ t 的 token（不看未来），保证历史 token 的结果不随新 token 改变——这是 KV cache 能成立的前提。

多头为什么要分开算再 flatten？ 因为 softmax 是非线性的：每个头需要独立的打分→独立的权重分布（不同视角关注不同内容）。若按 32768 维整体算，64 个视角的分数会被加总平均掉。flatten 只能发生在 softmax 之后。

最简实现：

DSV4 的优化（L537-542）：Wo 也做低秩分解（wo_a 分 8 组压到 1024 → wo_b 合到 4096），同 wq_a/wq_b 的套路，省参数省带宽。

  • 输入：[S, 64, 512] → 输出：[S, 4096]
  • 为什么必须回到 4096：残差相加要求维度一致，且下一层入口是 4096。

3.2 残差连接

作用：信息高速公路——即使某层没学到东西，原始信息也能无损传到后面；梯度也能直接回传，深层网络才可训练。

DSV4 的优化（Hyper-Connections, L647-700）：残差不是 1 份而是 hc_mult=4 份隐藏状态并行流动，用可学习的 Sinkhorn 权重混合（hc_pre 压缩 4→1 进子层，hc_post 展开 1→4）。理解成"4 车道残差"即可，不改变主干形状语义。

3.3 MoE（前馈网络）

最简实现（稠密 FFN）

每个 token 独立过一个两层 MLP：

没有头的概念，没有 flatten——处理的就是完整 4096 维向量。

DSV4 的优化（MoE，混合专家）

参数 ×8（容量大），每个 token 只激活 2 个专家（计算省）——稀疏激活。

  • 输入：[S, 4096] → 输出：[S, 4096]（形状不变）
  • 注意力的"分工"是按维度切（64 个头各看一个切片）；MoE 的"分工"是按 token 分（不同 token 走不同专家），每个专家处理完整向量。

4. 步骤三：输出层与采样

最简实现（输出层）

7 层 Block 输出 h [S, 4096]。第 i 行含义：“读完前 i+1 个 token 后，对下一个词的预测依据”。

W.T 的转置只是因为 PyTorch 存 [out, in]，数学要用 [in, out]；h @ W.T = 与词表每个词各做一次点积的打包。W 和嵌入表 E 形状相同、作用相反：E 是"词→向量"入口，W 是"向量→词"出口。

为什么只取最后一行？ 第 i 行预测的是第 i+1 个词——推理时那些词已经在输入里了，只有最后一行预测的是未知未来。不是近似，是无用的行干脆不算。

采样（L4 步变成真正的词）

为什么要采样而不是永远选最高分？ 避免输出死板、避免陷入重复循环；这也是同一问题问两次回答不同的原因。

DSV4 的优化（ParallelHead）

ParallelHead（L703）：W 按词表维度多卡切分 + all_gather 合并；权重存 fp32 保证打分精度。

5. Prefill vs Decode：两种工作模式

由于因果掩码，追加新 token 不改变历史 token 的任何计算结果——这是整个推理优化的基石。

Prefill（处理整段 prompt，start_pos == 0）

Decode（逐 token 生成，start_pos > 0）

形状不对称的含义：提问者只有一个（q 一行），被提问的是全部历史（kv 整个 cache）。

为什么不觉得越生成越慢？

  1. decode 注意力是 q[1] × kv[N]，O(N×d) 级别；真正的大头是每步读几十 GB 权重（与 N 无关），decode 是 memory-bound，注意力的增长被淹没。
  2. DSV4 的滑动窗口（128）+ 压缩 + 稀疏 topk（512）让实际参与计算的 kv 数量有上限。
  3. prefill 的 S×S 虽大，但并行矩阵乘且只发生一次。

8. 一句话总览

固定的权重，现场算的激活；token 向量在 7 层 Block 里反复经历"注意力（和历史交换信息）+ MoE（独立加工信息）"，每层进出都是 4096 维；最后取最后一行和词表矩阵点积打分，温度+top-k 采样出下一个词；prefill 一次算全段，decode 靠 KV cache 每步只算一行——这就是 DeepSeek-V4 的推理全貌。
