# DeepSeek-V4 前向传播全流程（推理视角）

> 基于 `model.py` 的推理代码，从用户输入到下一个 token 的完整过程。
> 每个步骤：**先讲最简实现 → 再讲 DSV4 的实际优化 → 标明输入/输出矩阵形状**。
>
> 全局超参数（`ModelArgs` 默认值）：
> ```
> dim = 4096          # 隐藏维度（全程的主干维度）
> vocab_size = 129280 # 词表大小
> n_layers = 7        # Block 层数
> n_heads = 64        # 注意力头数
> head_dim = 512      # 每头维度
> q_lora_rank = 1024  # Q 低秩压缩维度
> rope_head_dim = 64  # RoPE 位置编码维度
> n_routed_experts = 8, n_activated_experts = 2  # MoE：8 选 2
> window_size = 128   # 滑动窗口大小
> ```

---

## 0. 全局认知：两个角色

整个推理过程只有两种东西：

| 角色 | 内容 | 特点 |
|------|------|------|
| **权重（固定）** | 嵌入表 E、每层 wq/wkv/wo、专家矩阵、输出矩阵 W | 训练好后冻结，推理时只读；几十 GB，每步都要从显存读一遍 |
| **激活（现算）** | x、h、q、kv、logits | 根据输入现场计算，用完即弃（K/V 例外，会缓存） |

**推理 = 固定的知识 × 变化的输入 → 当场的预测。**

---

## 1. 总体执行框架

```
用户文本
   │
   ▼ ① 分词 + 嵌入查表
ids → x [S, 4096]
   │
   ▼ ② ×7 层 Block 循环（每层：Norm → Attention → 残差 → Norm → MoE → 残差）
h [S, 4096]     （形状守恒：进多少维出多少维）
   │
   ▼ ③ 输出层：取最后一行 @ W.T
logits [129280]
   │
   ▼ ④ 温度 + top-k 采样
下一个 token → 拼回输入 → 循环
```

---

## 2. 步骤一：分词与嵌入查表

### 最简实现（分词与查表）
分词器把文本切成 token id 序列；嵌入表 E 是一个 `[词表, dim]` 的矩阵，**按行号查表**（不是矩阵乘），每个 id 换一行向量。

```
"我爱吃" → ids [3] → 查 E → x [3, 4096]
```

- 输入：`ids [S]`（整数序列）
- 输出：`x [S, 4096]`（每行一个 token 的向量）

### DSV4 的优化（ParallelEmbedding）
`ParallelEmbedding`（L83）：多卡时把 E 按词表维度切分到不同显卡，各自查自己那一段再 `all_reduce` 合并。单卡时就是普通查表，无差别。

### 关键点
嵌入向量只是 token 的"原材料"。**decode 时历史 token 永不重新查表**——它们的贡献已经以 K/V 形式存进 KV cache 了。

---

## 3. 步骤二：Block 循环（×7 层）

每层 Block（L647）结构：

```
x [S, 4096]
  ├─ RMSNorm → Attention → +残差
  └─ RMSNorm → MoE       → +残差
输出 [S, 4096]     ← 形状守恒，才能无限堆叠
```

### 3.0 RMSNorm（归一化）

**最简实现**：把每个 token 的向量缩放为单位长度附近，再乘可学习的增益：

```
x / sqrt(mean(x²) + ε) × weight
```

- 输入：`[S, 4096]` → 输出：`[S, 4096]`（形状不变）
- 作用：稳定数值，防止层数堆叠后数值爆炸/消失。不改变语义方向的理解即可。

---

### 3.1 Attention（核心）

这是唯一发生 **token 之间信息交换** 的地方。其余所有操作都是逐 token 独立的。

#### 3.1.1 Q/KV 投影

**最简实现**（标准 Transformer）：

```
q = x @ Wq.T    # [S,4096] @ [4096, 64×512] → [S, 32768] → 拆头 [S, 64, 512]
k = x @ Wk.T    # 同形状
v = x @ Wv.T    # 同形状
```

含义：每个 token 生成三个角色——Q（我在找什么）、K（我是什么的标签）、V（我的实际内容）。

**DSV4 的优化（MLA，Multi-head Latent Attention）**：

```
① Q 低秩分解（L496-497）：一个大矩阵拆成两个小矩阵，参数省 72%
   x [S,4096] @ wq_a.T [4096→1024] → qr [S,1024]
   qr @ wq_b.T [1024→32768] → q [S, 64, 512]（拆出 64 个头）

② KV 合一（L502）：K 和 V 是同一个向量，一次算出，不分头！
   x [S,4096] @ wkv.T [4096→512] → kv [S, 512]
```

> **MLA 核心思想**：64 个头的多样性全部由 Q 侧承担（每个头的 q 不同，查同一份 kv 自然得到不同结果）；KV 只存一份共享的 512 维"信息浓汤"，既是 K 也是 V。
> **收益**：KV cache 每 token 只存 512 个数（标准 MHA 要存 64×512×2=65536 个），**省 128 倍显存**。

#### 3.1.2 RoPE 位置编码（L499、L504）

**最简实现**：纯注意力对顺序无感知，必须注入位置信息。RoPE 把 q/kv 的最后 64 维两两一组做旋转，旋转角度随位置变化，使得 `q_t · kv_s` 自动携带相对距离 (t−s) 的信息。

```
q[..., -64:], kv[..., -64:] 按位置旋转（形状不变）
```

**DSV4 细节**：只旋转最后 64 维（`rope_head_dim=64`），前 448 维保持内容纯净；且输出后要"反旋转"（L534），因为 kv 兼作 V，旋转会被加权求和带进输出。

#### 3.1.3 注意力核心计算

**最简实现**（三步）：

```
scores  = q · kvᵀ × (1/√512)      # 和历史每个 token 算相似度（点积）
weights = softmax(scores)          # 归一化成权重（每行和为 1）
o       = weights · kv             # 按权重加权融合历史信息
```

- 输入：`q [S, 64, 512]`，`kv [N, 512]`
- 输出：`o [S, 64, 512]`（列数跟随 V 的行维度）

> 矩阵乘法的每个元素就是一次点积：`q·kvᵀ` = q 和 kv 每一行分别点积的打包写法。
> `1/√512` 防止维度大时点积数值爆炸导致 softmax 饱和。
> **因果掩码**：位置 t 只能看 ≤ t 的 token（不看未来），保证历史 token 的结果不随新 token 改变——这是 KV cache 能成立的前提。

**多头为什么要分开算再 flatten？** 因为 softmax 是非线性的：每个头需要独立的打分→独立的权重分布（不同视角关注不同内容）。若按 32768 维整体算，64 个视角的分数会被加总平均掉。flatten 只能发生在 softmax 之后。

**DSV4 的优化**：

```
① 注意力 Sink（L456）：softmax 时多拼一个可学习的"虚拟 token"，
   给"其实不需要关注任何历史"的情况一个泄洪口。

② 滑动窗口 + 稀疏选择（L507-514）：不让 q 看全部历史——
   最近 128 个 token 的原始 kv（滑动窗口）
   + 更早历史的压缩 kv（Compressor 每 4/128 个 token 压成 1 个）
   + Indexer 从压缩 kv 里 top-512 稀疏挑选
   → topk_idxs 指定每个 q 实际参与计算的 kv 子集
   → sparse_attn（L528/533）只对选中的 kv 算注意力
   效果：注意力计算量有上限，不随序列无限增长。
```

#### 3.1.4 输出投影（回到 4096）

**最简实现**：

```
o [S, 64, 512] → flatten → [S, 32768] → @ Wo.T → [S, 4096]
```

**DSV4 的优化（L537-542）**：Wo 也做低秩分解（wo_a 分 8 组压到 1024 → wo_b 合到 4096），同 wq_a/wq_b 的套路，省参数省带宽。

- 输入：`[S, 64, 512]` → 输出：`[S, 4096]`
- 为什么必须回到 4096：残差相加要求维度一致，且下一层入口是 4096。

### 3.2 残差连接

```
x = x + attention(x)     # 逐元素相加，形状不变 [S, 4096]
```

作用：信息高速公路——即使某层没学到东西，原始信息也能无损传到后面；梯度也能直接回传，深层网络才可训练。

**DSV4 的优化（Hyper-Connections, L647-700）**：残差不是 1 份而是 `hc_mult=4` 份隐藏状态并行流动，用可学习的 Sinkhorn 权重混合（`hc_pre` 压缩 4→1 进子层，`hc_post` 展开 1→4）。理解成"4 车道残差"即可，不改变主干形状语义。

### 3.3 MoE（前馈网络）

#### 最简实现（稠密 FFN）

每个 token 独立过一个两层 MLP：

```
x [S,4096] → w1/w3 升维+激活（SwiGLU）→ w2 降回 → [S,4096]
```

没有头的概念，没有 flatten——处理的就是完整 4096 维向量。

#### DSV4 的优化（MoE，混合专家）

**参数 ×8（容量大），每个 token 只激活 2 个专家（计算省）**——稀疏激活。

```
① 路由打分（Gate, L565）：
   scores = x @ weight.T     # weight [8, 4096]，每个专家一行"特征模板"
   [S,4096] @ [4096,8] → [S,8]   # 每个 token 和 8 个专家的匹配度

② 选专家（L571-579）：
   sqrt(softplus(scores)) 激活 → + bias（只做选择、不扭曲权重，用于负载均衡）
   → top-2 选出 2 个专家

③ 权重归一化（L580-583）：选中专家的原始分数归一化（和为 1）

④ 加权混合（L635-643）：
   y = w₁·专家A(x) + w₂·专家B(x) + 共享专家(x)
```

- 输入：`[S, 4096]` → 输出：`[S, 4096]`（形状不变）
- 注意力的"分工"是按维度切（64 个头各看一个切片）；MoE 的"分工"是按 token 分（不同 token 走不同专家），每个专家处理完整向量。

## 4. 步骤三：输出层与采样

### 最简实现（输出层）

7 层 Block 输出 `h [S, 4096]`。第 i 行含义：**"读完前 i+1 个 token 后，对下一个词的预测依据"**。

```
取最后一行 h[:, -1]  [1, 4096]      # 只有它看过全部上下文
   │  @ W.T     W [129280, 4096]，每个词一行"特征模板"
   ▼
logits [1, 129280]                  # 和每个词做点积打分
```

> W.T 的转置只是因为 PyTorch 存 `[out, in]`，数学要用 `[in, out]`；`h @ W.T` = 与词表每个词各做一次点积的打包。W 和嵌入表 E 形状相同、作用相反：E 是"词→向量"入口，W 是"向量→词"出口。

**为什么只取最后一行？** 第 i 行预测的是第 i+1 个词——推理时那些词已经在输入里了，只有最后一行预测的是未知未来。不是近似，是无用的行干脆不算。

### 采样（L4 步变成真正的词）

```
logits / 温度T        # T小→差距放大→保守；T大→抹平→随机、有创意
softmax               # 变成概率（和为 1）
top-k 过滤            # 只留 k 个候选，其余清零，重新归一化
按概率掷骰子           # argmax（贪心）是 T→0 的特例
```

**为什么要采样而不是永远选最高分？** 避免输出死板、避免陷入重复循环；这也是同一问题问两次回答不同的原因。

### DSV4 的优化（ParallelHead）
`ParallelHead`（L703）：W 按词表维度多卡切分 + `all_gather` 合并；权重存 fp32 保证打分精度。

## 5. Prefill vs Decode：两种工作模式

由于因果掩码，**追加新 token 不改变历史 token 的任何计算结果**——这是整个推理优化的基石。

### Prefill（处理整段 prompt，`start_pos == 0`）

```
输入:  ids [S] → x [S, 4096]
过程:  整段一次过完所有层（矩阵×矩阵，GPU 并行，只发生一次）
       q [S, 64, 512]，kv [S, 512]
       scores [S, 64, N]（带因果掩码，下三角）
顺手:  把全部 token 的 kv 写入 KV cache
输出:  只取最后一行 → logits → 采样出第一个新 token
```

### Decode（逐 token 生成，`start_pos > 0`）

```
输入:  新 token id [1] → 只查 1 行嵌入 → x [1, 4096]
过程:  q 只有一行 [1, 64, 512]     ← 只有当前 token 需要"提问"
       kv 取 cache 全部 [N, 512]   ← 历史是"被查阅的资料"，必须全在
       新 token 的 kv 追加进 cache
       历史信息在注意力这一步注入：weights · kv（每层一次，7 层注入 7 次）
输出:  h_new [1, 4096] → logits [1, 129280] → 采样 → 下一个 token
```

**形状不对称的含义**：提问者只有一个（q 一行），被提问的是全部历史（kv 整个 cache）。

### 为什么不觉得越生成越慢？

1. decode 注意力是 `q[1] × kv[N]`，O(N×d) 级别；真正的大头是每步读几十 GB 权重（与 N 无关），decode 是 memory-bound，注意力的增长被淹没。
2. DSV4 的滑动窗口（128）+ 压缩 + 稀疏 topk（512）让实际参与计算的 kv 数量有上限。
3. prefill 的 S×S 虽大，但并行矩阵乘且只发生一次。

| Q 投影 | x `[1, 4096]` | wq_a `[1024, 4096]` → wq_b `[32768, 1024]` | q `[1, 64, 512]` |

## 7. Decode 逐矩阵追踪（完整版）

以 decode 为例，一个 token id 从进来到出下一个 token，每一步矩阵形状的完整变化。
（省略 batch 维；N = 历史 token 数，M = topk 实际选中的 kv 数）

### 第 0 步：嵌入查表

```
输入:  token id            [1]           （一个整数）
操作:  E[id] 查表          E: [129280, 4096]
输出:  x                   [1, 4096]
```

### 每层 Block 内部（×7 层，结构相同）

```
① Norm（形状不变）
   x [1, 4096] → RMSNorm → [1, 4096]

② Q 投影（两步低秩）
   [1, 4096] @ wq_a.T    wq_a: [1024, 4096]   → qr [1, 1024]
   q_norm 归一化（形状不变）                      → [1, 1024]
   [1, 1024] @ wq_b.T    wq_b: [32768, 1024]  → [1, 32768]
   unflatten(-1, (64, 512))                      → q [1, 64, 512]
   RoPE 旋转最后 64 维（形状不变）                 → q [1, 64, 512]

③ KV 投影（一次，K 兼 V）
   [1, 4096] @ wkv.T     wkv: [512, 4096]     → kv_new [1, 512]
   kv_norm + RoPE（形状不变）                    → [1, 512]
   写入 cache 一个槽位: kv_cache[.., start_pos % win, ..] = kv_new

④ 注意力（历史在此注入）
   输入:  q        [1, 64, 512]    ← 只有当前 token 一行
          kv_cache [N, 512]        ← 全部历史（窗口原始 + 压缩区）
   sparse_attn 内部:
     scores  = q · kv_selᵀ × 1/√512  → [1, 64, M]
     weights = softmax(+attn_sink)   → [1, 64, M]   每行和为1
     o       = weights · kv_sel      → [1, 64, 512]
   反 RoPE（形状不变）→ o [1, 64, 512]

⑤ 输出投影（64头汇合回 4096）
   o [1, 64, 512] → 分 8 组
   @ wo_a（每组 4096 → 1024 低秩）→ [1, 8, 1024] = [1, 8192]
   flatten @ wo_b.T    wo_b: [4096, 8192] → [1, 4096]

⑥ 残差汇合（Hyper-Connections）
   attn 输出 [1, 4096] 与 4 份残差按学习权重混合 → [1, 4096]（语义上 x + attn(x)）

⑦ MoE（逐 token 独立，无头）
   路由: [1, 4096] @ gate_weight.T  gate_weight: [8, 4096] → scores [1, 8]
         激活+bias → top-2 → 归一化权重 [1, 2]
   每个被选专家:
     [1, 4096] @ w1.T → silu → ┐
     [1, 4096] @ w3.T ────────┤ 相乘 → [1, 4096] @ w2.T → [1, 4096]
   汇合: y = w_a·专家A(x) + w_b·专家B(x) + 共享专家(x) → [1, 4096]
   + 残差 → [1, 4096]  ← 本层输出，交给下一层
```

### 输出层（7 层走完后）

```
h_new [1, 4096]  → 取最后一行（S=1 即它本身）
@ W.T   W: [129280, 4096]  → logits [1, 129280]
÷ 温度 → softmax → top-k → 采样 → 新 token id [1]
```

新 id 拼进上下文，`start_pos += 1`，回到第 0 步循环。

### 一图流

```
id[1]
 → E查表 → [1,4096]
 ┌────────────── ×7 层 ──────────────┐
 │ → Norm       [1,4096]             │
 │ → wq_a       [1,1024]             │
 │ → wq_b+拆头  [1,64,512]           │
 │ → wkv        [1,512] → 入cache    │
 │ → attn(cache[N,512]) [1,64,512]   │
 │ → wo_a/wo_b  [1,4096] +残差       │
 │ → Norm       [1,4096]             │
 │ → Gate       [1,8] → 选2专家      │
 │ → 专家w1/w3/w2 [1,4096] +残差     │
 └───────────────────────────────────┘
 → [1,4096] → @W.T → [1,129280] → 采样 → 新id[1]
```

**贯穿规律**：层内维度会膨胀/压缩（4096→1024→32768、→512、→8192），但每层的入口和出口永远回到 `[1, 4096]`（残差主干道）；唯一的"对外查询"是注意力对 `kv_cache [N, 512]` 的一次阅读。

---

## 8. 一句话总览

> 固定的权重，现场算的激活；token 向量在 7 层 Block 里反复经历"注意力（和历史交换信息）+ MoE（独立加工信息）"，每层进出都是 4096 维；最后取最后一行和词表矩阵点积打分，温度+top-k 采样出下一个词；prefill 一次算全段，decode 靠 KV cache 每步只算一行——这就是 DeepSeek-V4 的推理全貌。
